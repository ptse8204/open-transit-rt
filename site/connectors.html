Connector catalog

Choose a local connector shape before real integration work.

Open Transit RT connectors are sidecars, command adapters, manifests, or connector processes. They are not arbitrary dynamic backend code, and the examples here are synthetic or disabled by default.

These paths do not prove compliance, production readiness, consumer acceptance, vendor compatibility, hardware certification, hosted service availability, SLA coverage, production AVL reliability, production-grade ETA quality, or real-world ETA accuracy.

Vehicle / GPS / AVL

Bring observations to telemetry

CSV replay adapter, HTTP polling adapter, webhook sidecar adapter, generic JSON transform adapter, vendor-shaped synthetic examples, and authenticated POST /v1/telemetry.

Prediction

Keep ETA work replaceable

Deterministic built-in predictor, external HTTP predictor adapter, shadow-mode predictor, fail-closed behavior, and TheTransitClock candidate notes only.

Validator

Run allowlisted checks

MobilityData static GTFS validator, MobilityData GTFS Realtime validator, allowlisted validator IDs, and private validation health.

Monitoring / Export

Export local health safely

Local health summaries, operations notify draft, monitoring/export helper, and deployment-owned monitoring boundary.

Consumer / Discovery

Review feed metadata

/public/feeds.json, static GTFS URL, Vehicle Positions URL, Trip Updates URL, Alerts URL, and draft packet review without submission or acceptance claims.

Future Extension Model

Prefer manifests and sidecars

Manifest-based sidecars, no arbitrary dynamic backend plugin loading, and conformance tests required.
