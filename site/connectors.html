Connector catalog

Choose a local, safe connector shape before any real integration work.

Open Transit RT connectors are sidecars, command adapters, manifests, or connector processes. They are not arbitrary dynamic backend code, and the examples here are synthetic or disabled by default.

These paths do not prove compliance, production readiness, consumer acceptance, vendor compatibility, hardware certification, hosted service availability, SLA coverage, production AVL reliability, production-grade ETA quality, or real-world ETA accuracy.

Vehicle / GPS / AVL

CSV replay, HTTP polling, webhook sidecars, generic JSON transforms, vendor-shaped synthetic examples, and authenticated POST /v1/telemetry.

Prediction

Deterministic built-in predictor, external HTTP predictor adapter, shadow mode, fail-closed behavior, and TheTransitClock candidate notes only.

Validator

MobilityData static GTFS validator, MobilityData GTFS Realtime validator, allowlisted validator IDs, and private validation health.

Monitoring / Export

Local health summaries, operations notify draft, monitoring/export helper, and deployment-owned monitoring boundary.

Consumer / Discovery

/public/feeds.json, static GTFS, Vehicle Positions, Trip Updates, Alerts, and prepared-only packet review.

Future Extension Model

Manifest-based sidecars, no arbitrary dynamic backend plugin loading, and required conformance tests.
