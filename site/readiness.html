System check

Is it running?

Start by checking whether the schedule imported, the public feed URLs exist, realtime is publishing, vehicle data is fresh, and validators are available.

Fast answer

If a row is missing or blocked, open the linked browser page first. Ask for technical help only when the page says setup, tooling, secrets, or deployment work is needed.

Check These First

GTFS

Did the schedule import?

Open GTFS Import or GTFS Workbench and confirm an active feed version exists.

Feeds

Are five URLs available?

Check feeds.json, static GTFS, Vehicle Positions, Trip Updates, and Alerts.

Realtime

Are feeds publishing?

Review Vehicle Positions, Trip Updates diagnostics, Alerts, stale rows, and withheld output.

Vehicles

Is vehicle data fresh?

Check device bindings, last observations, stale counts, and assignment confidence.

Validators

Are validators installed?

Review validator health and latest static or realtime results when tooling is configured.

Issues

What needs attention?

Use feed health, GTFS quality, validation health, readiness, maintenance, and help pages.

What To Do Next

  1. Missing GTFSImport or publish a schedule before reviewing public feed health.
  2. Missing feed URLReview publication metadata and public base URL configuration.
  3. Stale vehicle dataCheck device bindings, telemetry source, connector setup, and stale threshold.
  4. Validator not availableAsk a technical helper to install or configure the allowlisted validator tooling.
  5. External sharingConfirm public hosting, license/contact metadata, and deployment ownership before sharing URLs.

For Public-Data Preparation

Open Transit RT supports CAL-ITP-style readiness workflows by making GTFS, GTFS-Realtime, discovery metadata, validation, and operations signals easier to review.

This local review is not a compliance decision, consumer submission, public listing, production launch, SLA, vendor certification, or ETA-quality proof.
