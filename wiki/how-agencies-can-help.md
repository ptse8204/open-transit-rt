# How Agencies Can Help

Open Transit RT improves fastest when agencies, civic technologists, operators,
and developer integrators try real evaluator workflows and share public-safe
feedback.

## Helpful Contributions

Agencies can help by:

- trying the [Small Agency Quick Start](small-agency-quick-start.md);
- walking the [browser-first setup path](browser-first-setup.md);
- testing with a public GTFS ZIP;
- reporting setup or validator blockers with exact commands;
- reviewing deployment docs for missing operational assumptions;
- contributing synthetic connector examples;
- sharing non-sensitive notes about GPS/AVL data shape;
- improving onboarding, runbooks, and troubleshooting docs;
- sponsoring or authorizing a later pilot if public launch evidence becomes a
  goal.

Formal agency approval, final feed-root evidence, and consumer acceptance are
not required to use or improve the software; they are future evidence
milestones only for agencies that choose public launch or compliance claims.

## What To Keep Private

Do not post:

- tokens, API keys, admin sessions, or device credentials;
- database URLs or private keys;
- private portal screenshots or private ticket links;
- raw private telemetry or raw vendor payloads;
- unredacted logs with credentials or private hostnames;
- personal data or operationally sensitive details.

Use redacted logs, public fixture shapes, and exact public-safe commands.

## Good First Contributions

- clarify a setup step that was confusing;
- add a synthetic fixture for an edge case;
- add an adapter example with no real credentials or vendor payloads;
- improve the connector cookbook;
- add tests around a small, reproducible bug;
- report where a command needs Docker, Java, validators, or network access.

For code and docs contribution rules, see [Support And Contribute](support-and-contribute.md)
and [CONTRIBUTING.md](../CONTRIBUTING.md).
